# Domain docs

Cómo deben consumir las skills la documentación de dominio de este repo.

## Leer antes de explorar

- `GLOSSARY.md` en la raíz (contexto único)
- `docs/adr/`: las ADR de la zona que se va a tocar

Si alguno no existe, seguir en silencio: no avisar ni proponer crearlo de antemano.

## Usar el vocabulario del glosario

Nombrar los conceptos con los términos de `GLOSSARY.md` (en tickets, tests, hipótesis).
No usar los sinónimos listados en `_Avoid_`.

## Marcar conflictos con una ADR

Si lo que se propone contradice una ADR, decirlo de forma explícita en vez de ignorarla.
